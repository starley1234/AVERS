## 1. Что это сейчас умеет (рабочий прототип)

Растровая или PDF-схема по ЕСКД → компоненты (УГО) с выводами и позиционными
обозначениями → netlist «компонент:вывод». Работает **на CPU без обученных
весов**.

| Стадия | Чем сделано | Статус |
|---|---|---|
| Детекция УГО | `GOSTTemplateDetector` — шаблоны библиотеки ГОСТ (31 класс) | работает |
| Разъёмы-таблицы, точки соединения | там же (`_detect_connector_tables`, `_detect_junction_dots`) | работает |
| OCR обозначений | EasyOCR + `avers/core/designators.py` (ГОСТ 2.710, `K1.1`, повторный проход по окрестности УГО) | работает |
| Векторизация проводов | `WireVectorizer` (Otsu → скелет → Hough → продление по штриху) | работает |
| Граф / netlist | `GraphBuilder` (пересечение без точки ≠ соединение) | работает |
| Обученные веса | `UltralyticsTiledDetector` + гибрид `refine()` | подключено, **модели нет** |
| Web UI, PDF, экспорт | FastAPI `avers/web` | работает |

## 5. План для следующего агента (по приоритету)

Перед любыми правками прогнать `venv\Scripts\python.exe -m pytest tests -q`
(ожидается 251 passed) и `scripts\stress_demo.py` (все варианты OK,
19/19, 11/11, 14/14). После правок — то же самое.

### A. Реальные данные (блокер для всего остального)
1. Попросить у пользователя 10–20 реальных листов БКС (сканы/PDF). Положить в
   `data/real/` и **не коммитить**, если они под NDA (добавить в `.gitignore`).
2. Разметить 3–5 листов эталоном в формате `*.netlist.json` (как у демо).
   Можно частично автоматически: прогнать пайплайн, поправить в валидаторе,
   выгрузить. Посчитать метрики `evaluate()`. Это и будет честная базовая
   линия.

### B. Синтетика и обучение (этапы 2–3, согласованы с пользователем как следующие)
1. Новый генератор на базе `demo_schematic._Sheet`:
   - случайные схемы, все 31 класс в пропорциях ГОСТ;
   - провода к выводам, обозначения, таблицы разъёмов;
   - повороты; эффекты скана (шум, размытие, JPEG, наклон ±1°);
   - отрицательные примеры: рамка/штамп ГОСТ 2.104, таблицы, текст;
   - разметка YOLO (bbox УГО вместе с выводами, как у шаблонов).
   CLI: `python -m avers.dataset.cli generate-v2 ...`.
2. Torch CUDA 12.8 (см. выше), обучение YOLO11s/m (imgsz 1024, 10–20 тыс.
   изображений; на RTX 5060 Ti порядка 1–3 ч). `avers/dataset/train.py` проверить
   и поправить (имена моделей, пути, `--device 0`).
3. Зарегистрировать веса в `ModelRegistry` и сделать `promote` (пайплайн
   подхватит сам) или указать `detection.model_path`.
4. Сравнить на демо, стресс-наборе и реальных листах: шаблоны / модель / гибрид.
   Включать по умолчанию только то, что лучше на реальных листах.

### C. Большие листы и PDF
1. Тайлинг в шаблонном детекторе для листов > `max_side`: масштаб по всему
   листу, сопоставление по тайлам с перекрытием, NMS по листу. Сейчас лист
   просто уменьшается до 1400 px.
2. OCR больших листов по тайлам вместо `canvas_size=4096`.
3. Векторный PDF: `page.get_drawings()` (PyMuPDF) → отрезки проводов и фигуры
   УГО напрямую, текст через `page.get_text("dict")`. Это точнее растра и не
   требует OCR.

### D. Специфика БКС в netlist
- Маркировка проводов и марки (БПВЛ-0,35, сечения) → `Net.net_name`,
  `wire_type`, `wire_color` (OCR текста вдоль провода → ближайшая цепь).
- Обрывы линий с адресами (`offpage_connector` + подпись) → объединение цепей
  между листами многостраничного PDF.
- Таблицы соединений и перечень элементов (ГОСТ 2.701) — сверка netlist с ними.

### E. Интерфейс и прочее

  (OCR/авто) и `pins_source`.

## 6. Стресс-набор для регрессии

`scripts/stress_demo.py` (с 15.10.2026):
```
venv\Scripts\python.exe scripts\stress_demo.py              # 10 вариантов, EasyOCR, ~2,5 мин
venv\Scripts\python.exe scripts\stress_demo.py --fake-ocr   # без OCR, ~1 мин

```
Варианты: исходник; ×0,75; ×1,35; шум `N(0, 18)`; `GaussianBlur(3, 0.8)`;
JPEG q60; контраст `0.75*img+50`; PDF (страница 1600×900 px при 150 dpi →
`load_and_process`); ×3 `INTER_NEAREST` (толстые линии); ×3 с линиями 2 px
(скелет штрихов, расширенный до 2 px; залитые точки соединения сохраняются).
Код возврата 1, если вариант ниже порога (19/19 компонентов, 11/11 цепей).
`--fake-ocr` подставляет подписи из эталона: проверяет детекцию, провода и
граф без EasyOCR.

В тестах: `tests/test_demo_schematic.py` (деградации, ×0,75, ×3 толстые и
тонкие линии с подставным OCR), `tests/test_designators.py` (настоящий EasyOCR,
если установлен).

Исправлено по итогам `thin` (было 18/19, 2/11):
- `template_detector.py`: при толщине линии < 2 px (после уменьшения листа до
  `max_side`) шаг масштаба шаблонов 4 % вместо 7 %, иначе реле K1 выпадало
  между шагами (контур за окном шаблона или покрытие < 0,85);
- `validators.py::_run_graph_synthesis`: вывод считается лежащим на краю bbox с
  допуском `2/scale_factor + 1` px вместо 3 px. На листе 4800 px детекция идёт
  при f≈0,29, и округление оставляло вывод в 4 px от края: его не сдвигали
  наружу, и он не доставал до провода;
- `graph_builder.py::build_graph`: для L-угла (конец отрезка у конца
  перпендикулярного) допуск ×1,5: оба отрезка отступают от скруглённого угла,
  зазор диагональный.

## 7. Ловушки (не наступать повторно)

- `opencv-python` vs `opencv-python-headless`: ставить ultralytics только
  `--no-deps`.
- PowerShell 5.1: `.ps1` с кириллицей — только UTF-8 **с BOM**; в `.cmd` —
  только ASCII (иначе после `chcp 65001` строки ломаются).
- Чтение JSON/текста в тестах на Windows — явно `encoding="utf-8"`
  (по умолчанию cp1251).
- Hough вероятностный: разные входы дают разное дробление отрезков. Любые
  «фиксированные пиксельные» допуски проверять на ×3 масштабе.
- В эталоне демо X1:1 и X1:3 объединяют цепи по обе стороны контакта —
  это намеренно (стыкуемые жгуты).
- Номера позиций ГОСТ 2.710 начинаются с 1: `R0` — ошибка OCR, не обозначение.
