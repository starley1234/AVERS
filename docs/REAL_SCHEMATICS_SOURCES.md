# Реальные советские/российские схемы — каталог источников для Active Learning (v0.3)

> Синтетика (`avers/dataset/synthetic.py`) и публичные англоязычные датасеты
> (`PUBLIC_DATASETS.md`) учат модель *общей форме* УГО. Но Active Learning Loop
> (валидатор → дообучение) раскрывается только на **настоящих** сканах — с их
> шумом, выцветшей печатью, рукописными пометками, наклоном и т.д. Этот документ —
> результат разведки (октябрь 2026) реальных, легко доступных источников схем на
> русском языке/из СССР, упорядоченных **от простого к сложному**, как и просил
> пользователь. Он должен дать агенту на GPU-машине достаточно материала, чтобы
> не тратить токены на собственный поиск.

Маленький курированный пример (12 изображений, покрывает все 4 уровня) уже лежит
в [`data/reference_schematics/`](../data/reference_schematics/README.md) — можно
сразу гонять pipeline/аннотатор, не скачивая ничего.

## Почему не настоящие схемы БКС?

Настоящие принципиальные схемы и схемы соединений бортовых кабельных сетей
самолётов/кораблей в подавляющем большинстве либо ведомственные, либо попросту
не выложены в открытый доступ (в отличие от схем бытовой техники/автомобилей).
Поэтому стратегия — **использовать лучший открытый структурный аналог** и
подниматься по сложности, прежде чем переходить на собственные (отсканированные
заказчиком) БКС-схемы, которые остаются золотым стандартом для финального
дообучения.

Ближайший легальный аналог БКС "схема соединений" (Э4 по ГОСТ 2.702) — это
**схемы электрооборудования автомобилей**: те же разъёмы с пронумерованными
контактами, "массы" (ground), жгуты проводов с цветовой/буквенной маркировкой,
реле, предохранители. Структурно это почти то же самое, только "изделие" —
автомобиль, а не самолёт/корабль.

## Tier 0 — ГОСТ УГО (тривиально)

Чистые, "векторные" иллюстрации отдельных условных обозначений — не полные
схемы, а таблицы символов. Полезно для сверки `avers/dataset/gost_symbols.py`
и как reference для разметчиков.

## Tier 2 — ламповые радиосхемы СССР (средне)

Меньше компонентов на схему, чем у автомобилей, зато **настоящие артефакты
скана**: шум, выцветшая печать, перекос — отличная тренировка устойчивости

| [radiolamp.net](https://radiolamp.net/news/4-priemniki-na-lampax/) | Ламповые приёмники от простых (1-V-1) до супергетеродинов, с описаниями | десятки |

## Tier 3 — грузовики/спецтехника (сложно)

Высокая плотность элементов, многолистовые схемы — ближе по масштабу к
настоящей БКС. Переходите сюда, когда модель уверенно работает на Tier 1/2.

| Источник | Что внутри | Объём |
|---|---|---|
| [almarka.ru — КамАЗ](https://almarka.ru/shema-jelektricheskaja-principialnaja-sistemy-upravlenija-jelektrooborudovaniem-kamaz-5490) | Принципиальные схемы системы управления электрооборудованием КамАЗ-5490 | несколько листов |
| [allautoinfo.org](https://allautoinfo.org/wiring-diagram/) | Схемы грузовиков/спецтехники, отечественной и зарубежной | десятки |

**Уже в репозитории:** `data/reference_schematics/tier3_complex_truck/` (3 файла).

Дополнительно поищите схемы: автобусов (ЛиАЗ, ПАЗ), тракторов (МТЗ/"Беларус"),
самосвалов (БелАЗ) — та же структура поиска ("схема электрооборудования <модель>
принципиальная").

## Tier 4 — теория и терминология БКС (для понимания домена)

Не содержит готовых изображений для обучения детектора, но критично для
правильной интерпретации того, что вы размечаете:

- [Habr — «Схемы электрические. Типы схем»](https://habr.com/ru/articles/451158/):
  наглядно объясняет разницу между Э1 (структурная), Э2 (функциональная), Э3
  (принципиальная), Э4 (соединений/монтажная — это и есть ближайший аналог
  выходного артефакта АВЕРС), Э6 (общая), Э7 (расположения), с иллюстрациями
  по ГОСТ 2.702-2011.
- [sciup.org — «Проектирование компонентов БКС ЛА»](https://sciup.org/proektirovanie-komponentov-bortovyh-kabelnyh-setej-s-uchjotom-trebovanij-170200576):
  формализация перехода Э3 → Э4 через топологический граф жгутов — хорошо
  ложится на `avers/stages/stage5_graph_synthesis`.
- ОСТ 1.00239-77 «Сети электрические бортовые летательных аппаратов» (ищется
  на opengost.ru) — конструктивные требования к жгутам, полезный контекст для
  доменных экспертов/аннотаторов.

## Международные датасеты (universal, не ГОСТ)

Уже подробно описаны в [`PUBLIC_DATASETS.md`](../PUBLIC_DATASETS.md) — Masala-CHAI,
ElectroNet, Roboflow Circuit Diagram, Digitize-HCD и др. Они используют
англоязычную схемотехническую нотацию (не ГОСТ), но форма базовых компонентов
(резистор-зигзаг, диод-треугольник) универсальна — годится для pre-training
перед fine-tuning на ГОСТ-данных из этого документа.

## Как масштабировать сбор на GPU-машине

1. **Каталог в коде:** `python -m avers dataset real-schematics list [--tier tierN]`
   (реализовано в `avers/dataset/real_schematics.py`) печатает этот же список
   программно.
2. **Ручная курация, не слепой краулинг.** Откройте источник, просмотрите
   галерею, скопируйте прямые URL картинок, которые действительно хотите
   использовать, в текстовый файл (по одному на строку).
3. **Скачивание с уважением к серверу:**
   ```bash
   python -m avers dataset real-schematics fetch --urls-file urls.txt --output data/reference_schematics/tier1_simple_car/raw --delay 1.0
   ```
   (`fetch_urls()` делает паузу между запросами и использует понятный
   User-Agent; папка `raw/` в `.gitignore`, в git не попадёт).
4. **Разметка:** `python -m avers web --port 8030` → `/annotator` → экспорт
   YOLO (train/val split).
5. **Слияние с синтетикой перед обучением** (важно — не обучайте только на
   маленьком реальном наборе, чтобы не забыть редкие классы):
   ```python
   from avers.dataset.merge import DatasetSource, merge_datasets
   merge_datasets([
       DatasetSource("synthetic", Path("/tmp/avers_gost/dataset.yaml"), weight=1),
       DatasetSource("real_tier1", Path("/tmp/real_tier1_export/dataset.yaml"), weight=5),
   ], Path("/tmp/avers_merged"))
   ```
6. Повторяйте для Tier 2 → Tier 3, добавляя всё более сложные схемы по мере
   роста точности модели — это и есть суть active learning: не распыляться
   на сложные случаи, пока не закрыты простые.

## ⚠️ Лицензии и этика

Все перечисленные сайты — энтузиастские архивы/форумы, сканы десятилетиями
перепечатываются без явного правообладателя. Это приемлемо для **внутреннего
R&D и обучения моделей** (аналогично тому, как академические CV-датасеты часто
строятся на скрейпинге технической литературы), но:

- не публикуйте скачанные сканы отдельно от приватного проекта;
- указывайте источник (URL) в метаданных датасета (как это делает
  `manifest.json` для курированного примера);
- для любого **публичного релиза** АВЕРС как продукта — используйте только
  собственные сканы заказчика, синтетику, или источники с явной открытой
  лицензией (CC BY 4.0 / MIT, см. `PUBLIC_DATASETS.md`);
- уважайте `robots.txt` и не создавайте чрезмерную нагрузку на небольшие
  волонтёрские сайты (отсюда `delay_sec` в `fetch_urls()`).
