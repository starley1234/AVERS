# Проверка геометрии проводов на реальных сканах

Срез проверки: октябрь 2026, CPU без обученных весов УГО и OCR-бэкенда.
Это проверка **геометрии**, не качества полноценного семантического netlist.

## КУБ-4 — чёрно-белая радиосхема

- Файл: `data/reference_schematics/tier2_medium_radio/tube_radio_kub4_01.png` (1222×711).
- Источник: http://radiolamp.net/news/374-sxema-korotkovolnovogo-priemnika-kub-4.html
  (условия использования — `data/reference_schematics/README.md`).
- До фильтрации пунктирной рамки и подтверждения разрывов исходными пикселями:
  128 цепей / 340 нарисованных отрезков; нижняя шина около y≈663 была разбита
  между NET_039, NET_049, NET_057 и NET_005.
- После изменений: 80 цепей / 348 отрезков (в том числе подтверждённые короткие
  перемычки). Нижняя шина y≈663 попадает в одну цепь. Отдельные фрагменты рамки
  и надписей ещё ошибочно считаются проводами.
- Компонентов и контактных соединений: 0, поскольку обученной модели нет.

Число цепей **не является метрикой точности**: для оценки precision/recall нужен
размеченный эталон. Склейка по непрерывному штриху консервативна, но на плотной
схеме всё ещё возможны как ложные соединения, так и разрывы.

## ВАЗ-2101 — цветная схема

- Файл: `data/reference_schematics/tier1_simple_car/vaz_2101_wiring_02.jpg` (960×560).
- Источник: https://www.drive2.ru/l/2054382/
- Текущий CPU-результат: 768 цепей / 4761 отрезок, 0 компонентов. Цветные
  проводники, легенда и символы сильно фрагментируют граф; **этот результат
  нельзя использовать как готовый netlist**.

## Как воспроизвести

```bash
python -m avers web  # порт 8030 по умолчанию
# Загрузить указанный файл и открыть вкладку «Цепи»
python -m pytest tests/test_graph_topology.py tests/test_wire_vectorizer.py -q
```

Для настоящих соединений между компонентами необходимы обученные веса детектора,
OCR и размеченные реальные схемы для валидации. До этого следует показывать
предупреждение о неполной обработке, а не объявлять результат корректным.
